# Blade Templates: Reusable Views

> [!abstract] In one paragraph
> A view is the part of a Laravel application that produces the HTML sent to the browser. Views are Blade files stored in `resources/views` with the `.blade.php` extension. A route or controller returns a view with `view('name')` and passes it data. Blade mixes static HTML with dynamic parts: `{{ }}` prints escaped values, `@if` and `@foreach` choose and repeat markup, `@extends` / `@section` / `@yield` share a common template, and `@include` inserts reusable fragments.

> [!info] Scope
> This note summarizes pages 1–25 of the VuesBlade course: views, parameterized views, Blade syntax, conditions, loops, layouts, sections, and includes. It stops there.

## 1. What a Blade view is

In a real application, the HTTP response is rarely produced directly by a route. The HTML is generated by a **view**, so that presentation lives in separate files and the same page structure can be reused. In its simplest form, a view is just a file containing HTML.

A view is a file in `resources/views` whose name ends with `.blade.php`. It contains static HTML and dynamic parts that Blade replaces when the page is rendered.

```text
resources/views/
├── home.blade.php              → view('home')
├── users/
│   ├── index.blade.php         → view('users.index')
│   └── show.blade.php          → view('users.show')
└── partials/
    └── header.blade.php        → view('partials.header')
```

The dot notation is the key idea: `users.index` means the file `resources/views/users/index.blade.php`. Laravel adds the `.blade.php` extension itself.

> [!note] Creating a view
> Create the file by hand in `resources/views`. The Artisan command `php artisan make:view nomVue` also generates it.

### 1.1 Returning a view

A view can be returned from a route or from a controller:

```php
Route::get('/', function () {
    return view('home');
});
```

```php
class WelcomeController extends Controller
{
    public function index()
    {
        return view('home');
    }
}
```

### 1.2 Parameterized views

Most views need data. Consider this URL:

![[Parameterized URL.excalidraw|1000]]

- The **base** of the URL is constant for the site.
- The **fixed part** here is the `home` route.
- The **variable part** is the person's first and last name.

**The route**, with a regex constraint on each parameter:

```php
Route::get('home/{prenom}/{nom}', [WelcomeController::class, 'index'])
    ->where([
        'prenom' => '[a-zA-Z]+',
        'nom' => '[a-zA-Z]+',
    ]);
```

**The controller** receives the parameters and passes them to the view:

```php
class WelcomeController extends Controller
{
    public function index($prenom, $nom)
    {
        return view('home', ['fname' => $prenom, 'lname' => $nom]);
    }
}
```

### 1.3 Three ways to pass data

All three syntaxes send data to the view. The variable names available inside the Blade file differ.

**Associative array** — the view receives `$fname` and `$lname`:

```php
return view('home', ['fname' => $prenom, 'lname' => $nom]);
```

**`compact()`** — the view receives `$prenom` and `$nom`:

```php
return view('home', compact('prenom', 'nom'));
```

**`with()`** — the view receives the keys given to `with`:

```php
return view('home')->with(['prenom' => $prenom, 'nom' => $nom]);

// A single variable
return view('home')->with('prenom', $prenom);
```

> [!warning] Names matter
> `['fname' => $prenom]` creates `$fname` in the view, not `$prenom`. `compact('prenom')` creates `$prenom`. Choose one style and stay consistent inside a feature.

> [!note] Blade compiles to PHP
> You do not need to write `<?php echo … ?>` in a Blade file. Blade translates your template into plain PHP once, stores the compiled version in `storage/framework/views`, and reuses it until the source file changes. This is why Blade stays fast even though it is a template engine.

## 2. Printing data

The double braces print a value and escape it for HTML:

```PHP
<h1>Bonjour {{ $nom }}</h1>
```

This is equivalent to the old PHP line:

```php
<?php echo "Bonjour " . e($nom); ?>
```

The `e()` helper escapes HTML special characters. If `$nom` contains `<script>alert('x')</script>`, the browser displays the text instead of running the script.

### 2.1 Comments

Blade comments are removed before the HTML is sent to the browser:

```PHP
{{-- This comment is never sent to the browser --}}

<!-- This HTML comment is sent to the browser -->
```

Use `{{-- --}}` for notes about the template itself.

### 2.2 Objects

Object properties use the arrow syntax:

```php
L'id est : {{ $user->id }}
Son prénom : {{ $user->prenom }}
Son nom : {{ $user->nom }}
```

If the object defines `__toString()`, printing the object directly also works, but accessing the property you need is clearer.

### 2.3 Checking that a variable exists

`@isset` and `@empty` protect a page when a variable may be missing:

```php
@isset($nom)
    <h1>Bonjour {{ $nom }} !</h1>
@endisset

@empty($nom)
    <h1>Nom non renseigné</h1>
@endempty
```

| Directive | True when |
|---|---|
| `@isset($x)` | `$x` exists and is not `null` |
| `@empty($x)` | `$x` is empty: `null`, `''`, `0`, `[]`, or an empty collection |

> [!warning] isset() inside @if keeps its PHP syntax
> `@isset($x)` is a Blade directive, but `@if(isset($x))` uses the normal PHP function. Both work, but do not mix the two forms:
>
> ```php
> @if (isset($user))
>     Bonjour {{ $user->nom }}
> @endif
> ```

### 2.4 Raw HTML

`{!! !!}` prints a value **without escaping**:

```php
<p>{!! $unsafeHtml !!}</p>
```

> [!danger] Never print user input with {!! !!}
> If `$unsafeHtml` comes from a form, a URL, or a database field the user controls, raw output can inject JavaScript or broken markup. Use `{!! !!}` only for HTML you generated yourself and fully trust.

## 3. Conditions

Blade provides directives that read like HTML tags around the markup they control.

### 3.1 `@if`, `@elseif`, `@else`

```php
@if ($user)
    Hello, {{ $user->nom }}
@elseif ($guest)
    Hello, invité
@else
    Hello, Guest
@endif
```

### 3.2 `@switch`

```php
@switch($i)
    @case(1)
        Premier cas…
        @break

    @case(2)
        Second cas…
        @break

    @default
        Cas par défaut…
@endswitch
```

> [!tip] Conditions choose markup, not business rules
> A view may decide whether to show an admin badge. It should not decide whether the user *is* an admin. Put that decision in the controller or middleware and pass a simple boolean to the view.

## 4. Loops

### 4.1 The three loops

```php
@for ($i = 0; $i < 10; $i++)
    <li>Élément n° {{ $i }}</li>
@endfor

@foreach ($users as $user)
    <li>{{ $user->name }}</li>
@endforeach

@while ($condition)
    <li>Encore une ligne</li>
@endwhile
```

In practice, `@foreach` is the loop you will use most often, because controllers usually pass collections or arrays to views.

### 4.2 Skipping and stopping

`@continue` skips the current iteration; `@break` ends the loop.

```php
@foreach ($users as $user)
    @continue($user->type == 1)

    <li>{{ $user->name }}</li>

    @break($user->number == 5)
@endforeach
```

The long form is also valid:

```php
@foreach ($users as $user)
    @if ($user->type == 1)
        @continue
    @endif

    <li>{{ $user->name }}</li>

    @if ($user->number == 5)
        @break
    @endif
@endforeach
```

### 4.3 @forelse and the empty case

`@forelse` works like `@foreach`, but provides an `@empty` block when the collection has no items:

```php
@forelse ($users as $user)
    <li>{{ $user->name }}</li>
@empty
    <li>Aucun utilisateur</li>
@endforelse
```

> [!tip] Prefer @forelse over an empty @foreach
> It removes the need for a separate `@if ($users->isEmpty())` before the loop, and it keeps the empty state next to the list it belongs to.

### 4.4 The $loop variable

Inside a `@foreach` or `@forelse`, Blade provides a `$loop` object describing the current iteration:

```PHP
@foreach ($users as $user)
    @if ($loop->first)
        <p>Début de la liste</p>
    @endif

    <li>{{ $loop->iteration }}. {{ $user->name }}</li>

    @if ($loop->last)
        <p>Fin de la liste</p>
    @endif
@endforeach
```

| Property | Meaning |
|---|---|
| `$loop->index` | Zero-based position |
| `$loop->iteration` | One-based position |
| `$loop->first` | True on the first item |
| `$loop->last` | True on the last item |
| `$loop->even` / `$loop->odd` | Parity of the iteration |
| `$loop->count` | Total number of items |
| `$loop->remaining` | Items left after the current one |

> [!note] $loop is local to each loop
> If loops are nested, the inner loop has its own `$loop`. Use `$loop->parent` to reach the outer loop's information.

## 5. Layouts and sections

### 5.1 The problem: repeated HTML

Imagine two pages, one for an article and one for an invoice. Without a layout, both files repeat the same document structure:

```php
<!DOCTYPE html>
<html>
<head>
    <title>Les articles</title>
    <meta charset="UTF-8">
</head>
<body>
    <p>C'est l'article n° {{ $numero }}</p>
</body>
</html>
```

```php
<!DOCTYPE html>
<html>
<head>
    <title>Les factures</title>
    <meta charset="UTF-8">
</head>
<body>
    <p>C'est la facture n° {{ $numero }}</p>
</body>
</html>
```

The `<html>`, `<head>`, and `<body>` tags are identical. Only the title and the body content change. A layout extracts the common part.

### 5.2 The layout template

```php
{{-- resources/views/layouts/app.blade.php --}}
<!DOCTYPE html>
<html>
<head>
    <title>@yield('title', 'Mon application')</title>
    <meta charset="UTF-8">
</head>
<body>
    @yield('content')
</body>
</html>
```

`@yield('title', 'Mon application')` marks a place where a child view may inject content. The second argument is the default used when the child does not provide a section.

### 5.3 A child view

```php
{{-- resources/views/article.blade.php --}}
@extends('layouts.app')

@section('title', 'Les articles')

@section('content')
    <p>C'est l'article n° {{ $numero }}</p>
@endsection
```

```php
{{-- resources/views/facture.blade.php --}}
@extends('layouts.app')

@section('title', 'Les factures')

@section('content')
    <p>C'est la facture n° {{ $numero }}</p>
@endsection
```

| Directive | Job |
|---|---|
| `@extends('layouts.app')` | Declares which layout this view uses |
| `@section('title') … @endsection` | Defines a named block of content |
| `@section('title', 'Les articles')` | Short form for a one-line section |
| `@yield('content')` | Prints the section supplied by the child view |

### 5.4 How the pieces fit together

![[Blade Composition.excalidraw|1000]]

The child view does not include the layout; it *extends* it. Blade renders the layout, and each `@yield` is replaced by the matching `@section` from the child. A section the child does not define falls back to the `@yield` default, or prints nothing.

The controller behind those pages passes the data each child view displays:

```php
class PageController extends Controller
{
    public function article($numero)
    {
        return view('article', ['numero' => $numero]);
    }

    public function facture($numero)
    {
        return view('facture', ['numero' => $numero]);
    }
}
```

> [!important] One layout, many pages
> Every page can extend the same layout and provide only its title and content. Changing the header, footer, or navigation then means editing one file, not every page.

> [!warning] @extends must be the first Blade directive
> Put `@extends` at the top of the child view, before any HTML or other directive. Content written before it is not handled as a section and can produce unexpected output.

## 6. Includes: reusing fragments

A layout is not the only reusable piece. A page can also insert a small fragment — a header, a footer, a navigation bar, a flash message.

### 6.1 @include

`@include` inserts another Blade view at the exact point where the directive is written:

```php
@include('partials.header')
```

The argument is a **view name**, not a file path. Blade applies the same dot notation as `view()`: `partials.header` resolves to `resources/views/partials/header.blade.php`.

The example uses three files. First, a reusable header partial:

```php
{{-- resources/views/partials/header.blade.php --}}
<header>
    <h1>Mon Application</h1>
    <nav>
        <ul>
            <li><a href="/">Accueil</a></li>
            <li><a href="/about">À propos</a></li>
        </ul>
    </nav>
</header>
```

Then a reusable footer partial:

```php
{{-- resources/views/partials/footer.blade.php --}}
<footer>
    <p>&copy; {{ date('Y') }} Mon Application. Tous droits réservés.</p>
</footer>
```

Finally, a page that inserts both fragments inside its content section:

```php
{{-- resources/views/home.blade.php --}}
@extends('layouts.app')

@section('content')
    @include('partials.header')

    <h2>Bienvenue sur notre site Laravel</h2>
    <p>Voici le contenu principal de la page d'accueil.</p>

    @include('partials.footer')
@endsection
```

When Blade renders `home.blade.php`, it replaces each `@include(...)` with the rendered contents of that partial. The page keeps its own layout, title, and section structure; the partials only supply the fragments.

| Piece | Role |
|---|---|
| `partials.header` | The reusable markup for the page header |
| `partials.footer` | The reusable markup for the page footer |
| `home.blade.php` | The page that decides where the fragments appear |

> [!note] Includes are not layouts
> An include is inserted *inside* a view that is already rendering. It does not become the page skeleton. Use `@include` for headers, footers, navigation bars, and small repeated fragments; use `@extends` and `@section` for the page skeleton.

> [!tip] Variables are shared
> An included partial can use the variables available to the parent view. Section 6.2 shows how to pass extra variables to an include.

### 6.2 Passing data to an include

```php
{{-- resources/views/partials/message.blade.php --}}
<div class="alert alert-info">
    {{ $message }}
</div>
```

```php
@include('partials.message', ['message' => 'Bienvenue sur notre site Laravel!'])
```

The second argument is an array of variables that become available inside the partial.

### 6.3 Defensive includes

| Directive | Behaviour |
|---|---|
| `@include('partials.special')` | Fails if the file does not exist |
| `@includeIf('partials.special')` | Includes it only when it exists |
| `@each('partials.user', $users, 'user')` | Includes `partials.user` once per item |

```php
@includeIf('partials.specialMessage', ['message' => 'Bonjour!'])
```

```php
@each('partials.user', $users, 'user')
```

`@each` is a compact way to render a list where every item uses the same partial. It is equivalent to a `@foreach` containing one `@include`.

> [!note] Include or extend?
> `@include` inserts a fragment *inside* a view that is already rendering. `@extends` makes a view *become* the content of a layout. Use includes for headers, footers, and repeated fragments; use layouts for the page skeleton.
